Written 2026-08-24, at the end of the v0.6.1 adversarial-hardening sprint. This is the
state a fresh session should start from. Read `docs/SUBMISSION_STATUS.md` and
`docs/internal/evidence.json` before trusting any number quoted anywhere else.

## Authority order for project state

When two sources disagree about what is true right now, believe them in this
order, and correct the loser rather than working around it:

1. The published GitHub release and the live Innovation Fund listing.
2. `docs/internal/evidence.json` (generated by `tools/evidence/update.py`).
3. `docs/SUBMISSION_STATUS.md` and `docs/TRUST_STATUS.md`.
4. Everything else, including README, CHANGELOG and any planning document.

Never turn a stale TODO into new work without first proving the task is
actually incomplete. Never resurrect finished work.

## What v0.6.1 was

An adversarial sprint: everything in it came from trying to make v0.6.0 lie, and
every fix was a defect in the published stable build. The full list is in
CHANGELOG.md; the ones worth carrying in your head:

- Studio could not read object names in real Snapmaker Orca jobs at all.
- Profile agreement (same printer, same spools) was being read as project identity.
- The folder watcher could offer a file that stopped part-way.
- Nothing re-read the world between the check and the send.
- A model's filename could reach a support bundle.
- The "Extended firmware" badge was a guess from macro count — and the positive
  probe written to replace it reported a *stock* U1 as extended, because the
  printer's web server answers every path with the same page. The real-U1 harness
  caught that one.

Two harnesses found defects the tests did not, which is the argument for keeping
them: the installed-build run and the real-printer run.

## Known limitations, stated publicly and still true

Windows only. Installer unsigned. Purge cannot be attributed to a single object.
Nozzle diameter is not readable from the job. Free storage is not exposed by
stock firmware — traced, not assumed, and reported as unknown. Painted colour
cannot be classified. Provenance can only answer `unknown` when a job carries
neither object names nor colour data. Remaining filament is known only where
something tracks it. Prusa projects are read in full; the print settings that mean the same thing on
both sides are carried into a prepared copy, and temperatures deliberately are not.

## Not started, and deliberately so

- Extended firmware enrichment. Detection exists and is positive-only; there is
  nothing Studio does with the answer yet, and inventing a use would be worse than
  leaving it.
- Prusa preparation beyond the settings whose meaning survives the crossing. What
  is carried and what deliberately is not is in `prusa.CARRIED` and `not_carried`.
- U1Hub adapter — it exposes no interface it means to offer. The proposal for one
  is in `docs/interop/U1HUB_INTEROP_PROPOSAL.md`; until it exists, Studio depends
  on nothing of U1Hub's and reads none of its files.

## The three genuine human gates

Everything up to each of these is already prepared.

1. **Send the drafted Innovation Fund listing correction.** The listing still
   carries an old description and cover image. The draft is written; sending it
   is the maintainer's to do.
2. **Post the community update.** Written and reviewed. Posting is under the
   maintainer's identity. No request for stars, no request for votes, no
   Innovation Fund lobbying.
3. **Submit the SignPath application** for a signed installer. The form accepts
   terms on the maintainer's behalf.

## Standing rules that bite most often

- Studio never slices, never takes autonomous control of a printer, never
  uploads anything anywhere, and never modifies an original file.
- Never force-kill a slicer, printer or user GUI process. Only processes this
  session started, tracked by PID.
- No local paths, usernames, hostnames, printer addresses or private model names
  in tracked files or screenshots. Anonymise evidence at the source.
- Unknown stays unknown. Withdraw an unprovable claim rather than patching it.
- Do not publish a prerelease to show progress, and do not hard-code a number
  that `evidence.json` already carries.
